# InkQuest 用户自主生成故事：功能与 UE 规划

> 状态：产品与交互方案草案  
> 核心体验：快速随机开局，边读边生成  
> 设计基底：Editorial 编辑室 × Playful 冒险细节  
> 适用人群：中文学习者与英文学习者

## 1. 产品定义

InkQuest 的生成故事功能不是一个“帮我写小说”的通用聊天框，而是一台让学习者快速进入故事、持续做选择、在需要时接管剧情的互动叙事引擎。

默认路径应极短：用户只需完成 2–3 次轻量选择，便可在约 10 秒内进入第一章。复杂的世界观、人物关系和导演指令不在开局时一次性索取，而是在阅读过程中渐进出现。

### 1.1 核心价值

- **先读起来**：以随机盲盒和三选一卡牌降低空白输入压力。
- **每次选择都有后果**：选择改变人物关系、线索和后续分支，而不仅是替换一句过场文案。
- **学习目标不打断故事**：词汇、难度和目标语言约束由系统持续维护。
- **为控制权付费**：基础价值是生成与阅读；高级价值是暂停、回溯、重掷和编辑故事世界。

### 1.2 非目标

- 首版不做专业长篇小说编辑器。
- 不要求用户在开局前填写完整世界观或角色档案。
- 不把对话框作为页面主角。
- 不承诺无限分支同时生成，也不展示虚假的百分比进度。
- 不在本阶段确定真实积分价格；所有成本均由后台配置。

## 2. 用户与使用场景

### 2.1 目标用户

1. **中文学习者**：以中文阅读故事，可按自身等级控制词汇和句法难度。
2. **英文学习者**：以英文阅读故事，沿用同一套生成、选择和学习辅助能力。
3. **轻度互动小说玩家**：希望快速开始，不愿先写长提示词。
4. **重度剧情玩家**：愿意付费获得 Director Mode，对世界观和人物关系进行细粒度控制。

### 2.2 关键任务

- “我现在就想随机开一个有趣的故事。”
- “我有一个大概想法，希望系统替我补全。”
- “我想继续读，并决定下一步发生什么。”
- “我不喜欢刚才的走向，想回退或重掷。”
- “我希望某个人物更信任我，或让故事更悬疑。”
- “故事要好看，但语言难度不能突然失控。”

## 3. 产品结构

```text
生成故事入口
├── 快速开局（默认）
│   ├── 目标语言
│   ├── 题材卡牌
│   ├── 开局身份卡牌
│   ├── 核心动机卡牌
│   ├── 可选 TTS
│   └── 全部随机 / 单项重抽
├── 自定义开局（渐进展开）
│   ├── 一句话想法
│   ├── 大纲或提示词
│   ├── 语言等级
│   └── 不希望出现的内容
└── 故事工作台
    ├── 阅读纸页（主区域）
    ├── 三个剧情选择
    ├── 生成与积分状态
    ├── 故事记录 / 回溯
    └── 剧情操控室 Director Mode（付费）
        ├── 临时导演指令
        ├── 人物关系卡
        ├── 世界设定集
        ├── 伏笔与剧情倾向
        └── 回溯 / 重掷
```

## 4. 核心体验原则

### 4.1 故事优先，不做聊天机器人

故事正文始终占据视觉主位。Director Mode 只在用户主动干预时出现，并明确区分三类信息：

- **故事内容**：排版在阅读纸页中。
- **可执行选择**：正文下方的三条路径。
- **导演指令**：右侧操控室或移动端抽屉中的独立输入区。

系统回复不应以连续气泡堆叠。导演指令提交后，用一条简洁的“已写入下一段”回执表示生效，结果仍然体现在故事正文里。

### 4.2 快速路径优先

默认只展示三个选择维度，每组当前只露出三张卡：

- 题材：悬疑 / 奇幻 / 都市等。
- 身份：失忆旅客 / 新手记者 / 临时翻译等。
- 动机：寻找失踪者 / 隐藏秘密 / 完成交易等。

用户可以：

- 点选卡牌；
- 单独重抽某一组；
- “全部随机”；
- 不做任何选择，直接使用系统预选组合开局。

### 4.3 渐进式控制

高级选项按意图出现，而不是全部摊开：

- 点击“写下你的想法”后才显示自由输入。
- 第一章生成后才显示人物关系和设定集。
- 用户首次尝试回溯、重掷或全局编辑时，再解释 Director Mode 的价值。
- 学习难度保持在个人偏好中，故事页只显示当前等级，不反复打断。

## 5. 关键用户流程

### 5.1 快速随机开局

1. 用户进入“生成故事”。
2. 系统读取账号中的目标语言和学习等级，并允许当场切换。
3. 系统预选一组题材、身份和动机。
4. 用户可点选卡牌或点击“全部随机”。
5. 主按钮显示本次预计积分消耗，价格由服务端配置。
6. 用户点击“生成第一章”。
7. 系统预留积分，创建故事与生成任务。
8. 页面进入真实阶段状态，如“正在整理人物动机”“正在写入开场”。
9. 第一段可读内容一旦完成立即呈现，不等待整章全部生成。
10. 三个选择准备完成后可点击，后台可继续准备短过渡段。

### 5.2 自定义开局

1. 用户展开“写下你的想法”。
2. 输入一句话主题、大纲或具体提示。
3. 系统将自由输入与所选卡牌合并，不要求用户二选一。
4. 若存在冲突，生成前只提示最重要的一处，例如“你选择了古代背景，但大纲中出现智能手机”。
5. 用户确认或让系统自动协调后开始生成。

建议自由输入区支持：

- 一句话想法；
- 多段大纲；
- 希望出现的角色或关系；
- 是否为每个新场景生成 TTS；
- 不希望出现的内容；
- “保留更多惊喜”开关。

### 5.3 边读边生成

1. 用户读完当前场景。
2. 页面展示三个选择，每个选择包含“动作 + 风险或倾向”，避免模糊按钮。
3. 用户选择后，卡牌立即锁定并显示一个短过渡反馈。
4. 系统只生成被选择的下一场景。
5. 已选分支写入时间线；其他分支保留为种子，不生成完整正文。
6. 下一段开始流式显示；完成后再次提供三个选择。

### 5.4 Director Mode

Director Mode 是“用户对未来剧情施加约束”的空间，不直接编辑已经发布到阅读纸页的正文。

用户可提交临时指令，例如：

- “下一段更紧张，但不要马上揭晓凶手。”
- “让林遥开始怀疑我。”
- “减少生词，保留对话节奏。”
- “把雨夜车站设为后续重要地点。”

指令分为两种作用域：

- **仅下一段**：一次性倾向，生成后自动归档。
- **持续生效**：写入人物卡、世界设定或风格约束，后续每轮带入。

### 5.5 回溯与重掷

- **重掷选项**：当前正文不变，仅重新生成三个下一步选项。
- **重写下一段**：保留用户选择，重新生成其结果。
- **回溯分支**：回到历史决策点，从另一分支继续。
- **恢复旧时间线**：回溯不会静默删除后续内容，旧线作为快照保留，直到用户主动清理。

所有操作都要在执行前展示积分影响和结果范围；不可恢复的清理才需要确认。

## 6. 页面与布局

### 6.1 桌面端：三栏 Workbench

| 区域 | 作用 | 设计重点 |
| --- | --- | --- |
| 左栏 | 开局设定、语言、积分、故事状态 | 紧凑工具栏；卡牌可快速重抽 |
| 中栏 | 故事正文与分支选择 | 最大视觉权重；纸页排版；生成中保持可读 |
| 右栏 | Director Mode | 默认安静；有指令时展开；不是永久聊天流 |

开局阶段中栏展示“即将生成的故事票据”：把已选择的题材、身份和动机组合成一句可读概述。生成后，中栏切换为阅读纸页。

### 6.2 移动端：顺序式工作流

- 顶部只保留返回、故事标题、积分三个必要信息。
- 开局时依次展示三个卡牌组，底部固定主按钮。
- 阅读时正文优先，选项紧跟正文。
- 左栏内容收纳进“故事设定”底部抽屉。
- Director Mode 作为底部工具入口打开全高抽屉，不与正文并排。
- 键盘弹起时输入区贴近可视区域底部，主按钮和抽屉均不横向溢出。

## 7. 生成与等待体验

### 7.1 推荐生成策略

每轮模型应返回：

1. 当前可读场景；
2. 三个分支选项；
3. 每个选项的短分支种子或过渡句；
4. 更新后的结构化故事状态摘要。

用户选择后，仅生成被选中的完整下一场景。这样比预生成三个完整分支更节省成本，也避免大量永远不会被阅读的内容。

### 7.2 有限预生成

可在资源允许时做谨慎预测：

- 第一章分两块生成：先返回开场，再缓冲一个桥接段。
- 选项出现后，可只预生成“最可能选择”的一个短过渡，不预生成完整场景。
- 预生成结果必须以 `story_state_hash + choice_id + generation_config_version` 作为缓存键。
- 用户修改 Director Mode 或设定集后，相关预生成缓存立即失效。

### 7.3 真实加载状态

使用与后端阶段对应的文案：

- 正在整理人物动机
- 正在建立开场冲突
- 正在写入这一段
- 正在准备三个去向
- 正在检查语言难度

不显示无法被准确计算的百分比。第一段可用时立即展示，选项仍在生成可使用占位状态，但不得让用户误以为可以点击。

### 7.4 可选 TTS

“语音朗读”属于故事级生成偏好，默认关闭，用户可选择“每段生成”。开启后：

- 每个新场景在正文完成后异步生成音频和词级时间戳；
- 生成前报价分别展示正文积分和 TTS 额外积分；
- 正文成功、TTS 失败时仍提交正文，并自动释放或退回 TTS 对应预留；
- 用户可稍后单独重试音频，不重新生成正文；
- 修改正文或回溯生成新版本后，旧音频不能继续绑定到新文本；
- 中文默认使用腾讯云 TTS，英文供应商通过统一接口选择，不在产品界面暴露底层厂商。

不建议在快速开局阶段让用户选择大量音色。首版只提供“暂不需要 / 每段生成”，音色选择可在阅读页的语音设置中渐进展开。

## 8. 积分与付费模型

### 8.1 计费原则

具体价格保持 `TBD` 并由后台配置，不在客户端硬编码。建议按用户能理解的动作收费，而不是暴露 token：

- 生成开场 / 下一段；
- 为开场 / 下一段生成 TTS；
- 重写当前段；
- 重掷选项；
- Director Mode 高级操作；
- 超长上下文或更高质量模型附加成本。

### 8.2 预留与结算

1. 请求开始前检查余额。
2. 创建积分预留记录。
3. 正文和 TTS 使用同一请求下的独立费用项预留。
4. 生成成功后按实际动作分别结算。
5. 某一子任务失败时只释放对应部分；全任务失败、超时或安全拒绝时释放全部预留。
6. 客户端使用幂等键，重复点击或网络重试不得重复扣费。

### 8.3 付费边界

建议采用“可体验，控制权付费”的结构：

- 用户可以体验快速开局和基础分支阅读。
- 积分用于持续生成，额度和赠送策略由商业方案决定。
- Director Mode、回溯重掷、全局人物关系和世界设定编辑属于高级能力。
- 触发付费墙时保留当前故事和输入，不让用户购买后重新填写。

## 9. 状态模型

每个故事需要保存结构化状态，而不能只保存聊天记录。

```ts
type StoryState = {
  storyId: string
  ownerId: string
  targetLanguage: "zh-CN" | "en"
  learnerLevel: string
  title: string
  premise: string
  status: "draft" | "generating" | "active" | "paused" | "archived"
  currentNodeId: string | null
  worldBible: WorldRule[]
  characters: CharacterCard[]
  relationships: RelationshipEdge[]
  timeline: TimelineEvent[]
  unresolvedThreads: StoryThread[]
  persistentDirectives: Directive[]
  safetyProfile: SafetyProfile
  generationConfigVersion: string
}
```

场景节点至少包含：正文、摘要、三个选项、父节点、被选选项、生成配置、积分交易、状态哈希和版本号。

### 9.1 人物关系卡

- 人物目标；
- 对主角的态度；
- 已知秘密；
- 当前关系变化；
- 不可违背的角色约束。

关系不建议用精确数值直接暴露给用户，可使用“戒备 / 动摇 / 信任”等叙事标签；内部可以保留结构化强度用于一致性判断。

### 9.2 世界设定集

分为：

- 硬规则：不可被下一段随意推翻；
- 软倾向：可被剧情逐步改变；
- 已确认事实：正文中已经发生；
- 未揭示设定：模型可用，但不应提前泄露给用户。

## 10. 后端与接口建议

### 10.1 服务拆分

- **Story Service**：故事、节点、分支、版本和权限。
- **Generation Orchestrator**：提示组装、模型调用、流式输出、重试和状态更新。
- **Credit Ledger**：预留、结算、释放、幂等记录。
- **Safety Layer**：输入与输出审核，年龄和内容偏好约束。
- **Learning Quality Layer**：词汇等级、句法复杂度和目标语言检查。

### 10.2 核心接口

```text
POST /api/generated-stories
POST /api/generated-stories/:id/opening
POST /api/generated-stories/:id/nodes/:nodeId/choose
POST /api/generated-stories/:id/nodes/:nodeId/reroll-options
POST /api/generated-stories/:id/nodes/:nodeId/rewrite
POST /api/generated-stories/:id/directives
PATCH /api/generated-stories/:id/characters/:characterId
PATCH /api/generated-stories/:id/world-rules/:ruleId
POST /api/generated-stories/:id/rewind
GET  /api/generated-stories/:id/events
```

生成接口返回任务 ID，通过 SSE 或现有流式通道推送阶段事件和正文片段。所有写操作携带 `Idempotency-Key`。

### 10.3 生成任务事件

```text
generation.reserved
generation.planning
generation.scene.delta
generation.scene.completed
generation.choices.completed
generation.quality_checked
generation.committed
generation.failed
credits.released
```

## 11. Prompt 与一致性策略

每次生成提示应由稳定层级组成：

1. 产品与安全规则；
2. 目标语言和学习等级；
3. 世界硬规则；
4. 人物卡与关系；
5. 时间线摘要和未解决伏笔；
6. 当前场景及用户选择；
7. Director Mode 持续指令；
8. 仅下一段的临时指令；
9. 输出结构 schema。

长故事不应无限携带全文。保留最近若干场景原文，其余内容压缩为可版本化摘要；关键事实单独存储，避免摘要覆盖硬规则。

## 12. 语言学习质量

- 目标语言必须贯穿正文、选项和 Director Mode 建议。
- 用户界面语言与故事目标语言可以不同。
- 生成后检查词汇难度、句长、专名一致性和代码切换比例。
- 专有名词、剧情关键用语可超出等级，但应进入可解释词汇列表。
- 不为了“简单”牺牲自然语言；优先缩短句法和降低低频词密度。
- 用户手动要求更难或更简单时，从下一段开始生效并记录为持续偏好。

## 13. 完整页面状态

| 状态 | 用户看到什么 | 可执行动作 |
| --- | --- | --- |
| 初始 | 三组预选卡、语言、TTS、示例积分 | 选择、随机、自定义、生成 |
| 自定义展开 | 输入区和轻量高级项 | 编辑、折叠、生成 |
| 积分预留 | 主按钮锁定，分别显示正文和 TTS 预留 | 取消尚未开始的任务 |
| 生成正文 | 流式正文，选项占位 | 阅读、停止语音等本地操作 |
| 等待选项 | 正文可读，选项仍准备中 | 等待，不可点击占位项 |
| 可选择 | 三个明确分支 | 选择、Director Mode、重掷 |
| 分支生成 | 选中项锁定，显示过渡与阶段 | 阅读历史、取消未提交任务 |
| 余额不足 | 保留所有输入和故事位置 | 获取积分、返回 |
| 生成失败 | 说明失败范围和积分状态 | 免费重试或修改输入 |
| TTS 失败 | 正文正常可读，语音标为未生成 | 单独重试语音 |
| 安全拒绝 | 指出不可生成的方向 | 修改提示，不扣或释放积分 |
| 离线 / 断线 | 保留本地输入并尝试恢复事件流 | 重连、稍后继续 |

## 14. 错误与边界情况

- 连续点击生成：以幂等键合并请求，按钮立即锁定。
- 用户刷新页面：从任务事件和已提交节点恢复，不重复生成。
- 生成正文成功但选项失败：保留正文，只免费重试选项阶段。
- 正文成功但 TTS 失败：提交正文、释放 TTS 预留，并创建可重试的独立音频任务。
- Director 指令与世界硬规则冲突：指出冲突，让用户选择修改哪一项。
- 输入超长：展示可接受范围和压缩建议，不静默截断。
- 多设备同时选择不同分支：先提交者成功，后提交者收到“故事已在另一设备继续”的可恢复提示。
- 回溯后继续：创建新时间线分叉，不覆盖旧节点。
- 余额在预留后变化：以已创建的预留记录为准。

## 15. 安全与内容治理

- 输入和输出都经过安全审核。
- 提供内容强度偏好，并根据账号年龄或地区策略限制可选范围。
- 对拒绝请求说明可以调整的方向，不输出模糊的“生成失败”。
- 用户自定义设定、故事正文和导演指令应有明确的数据保存与删除入口。
- 公开分享前执行额外审核；私有草稿与公开内容使用不同发布状态。

## 16. 数据与实验

以下均为待验证指标，不是既有数据：

- 进入页面到首次生成的耗时；
- 三组卡牌的完成率与“全部随机”使用率；
- 第一段完成阅读率；
- 每个故事的有效选择轮数；
- 生成等待期间的退出率；
- Director Mode 首次触发点与购买转化；
- 重掷、回溯和关系编辑的使用分布；
- 失败重试率、积分释放成功率；
- 语言难度手动调整率和生词查看率。

可优先验证：

1. 三组卡牌与单一“随机开局”按钮，哪种更能提高首章启动率；
2. 第一段先返回是否显著降低等待退出；
3. Director Mode 在第一次选择后提示，还是用户主动触发时提示更自然；
4. 选项展示“风险倾向”是否提高选择信心。

## 17. 分阶段上线

### Phase 0：交互验证

- 独立 Demo；
- 快速卡牌、随机、自定义输入；
- 模拟生成状态、选择和 Director Mode；
- 用户访谈验证信息结构和付费价值感。

### Phase 1：MVP

- 中文 / 英文目标语言；
- 快速开局和自定义一句话；
- 第一段 + 三选一 + 继续生成；
- 积分预留、结算、失败释放；
- 故事保存、恢复和基础安全审核；
- Director Mode 的“仅下一段”文本指令。

### Phase 2：剧情操控室

- 持续导演指令；
- 人物关系卡和世界设定集；
- 重掷、重写、回溯与时间线快照；
- 更完整的学习难度控制。

### Phase 3：长期创作系统

- 多章节结构与章节目标；
- 故事模板和可复用设定集；
- 私有分享 / 公开发布；
- 更智能的分支预测缓存；
- 创作者模式与协作能力（需单独评估）。

## 18. MVP 验收标准

- 用户无需输入文字即可完成开局。
- 从页面进入到发起首章生成不超过三个主要决策步骤。
- 320、375、414、768 px 宽度无横向滚动。
- 正文在选项生成失败时仍可保留并继续恢复。
- 每次扣费可追溯到具体生成动作，重复请求不重复扣费。
- 失败或安全拒绝会明确展示积分处理结果。
- 用户刷新后可恢复当前故事节点和未完成任务。
- 每个场景包含三个可区分且不互相同义的选择。
- 用户能区分“仅下一段”和“持续生效”的导演指令。
- 中文与英文故事均经过对应等级的语言质量检查。
- 开启 TTS 时，正文与音频分项结算；音频失败不阻塞正文阅读。

## 19. 建议的首版决策

1. **把“快速开局”定为唯一默认入口**，自定义输入作为展开项。
2. **第一章按两块交付**，先让用户阅读开场，再完成选项与后续缓冲。
3. **不预生成三个完整分支**，只生成分支种子和被选中的下一段。
4. **把付费价值聚焦为剧情控制权**，而不是只强调“更多生成次数”。
5. **首版 Director Mode 先做文本指令**，人物卡、设定集和回溯在第二阶段扩展。
6. **积分价格全部后台化**，前端只展示服务端返回的本次预计与最终消耗。
